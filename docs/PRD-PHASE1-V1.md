## 1. 产品目标

阶段1 MVP 要解决的核心问题是：**"我能看到用户评论了什么，但我不知道我的内容哪里做对了、哪里做错了。"** 当前系统止步于对评论打标签和分类，用户在看完信号面板后产生的第一个问题——"所以呢？我的内容要怎么改？"——无法得到回答。

阶段1 面向的用户角色是**品牌方内容负责人和代运营公司的内容策略师**。他们不需要理解AI如何工作，他们需要的是：一份清晰告诉TA"你的内容开头钩子吸引了正面共鸣，但第三个卖点引发了大量质疑，建议这样调整"的诊断报告，以及一份可以直接拿去拍摄的执行方案。

阶段1 的**成功标准**：一名未受过AI训练的用户，从创建任务到拿到一份可执行的内容生产卡，全程不超过 15 分钟（不含Agent推理耗时），且不需要额外解释任何技术概念。

## 2. 用户故事

### 2.1 模块6：内容-评论归因系统（核心新增）

| # | 用户故事 | 价值说明 |
|---|---------|---------|
| US-6.1 | 作为内容策略师，我想看到**归因矩阵**（内容要点 × 用户反应类型），以便一眼判断"内容的哪个部分引发了评论区的哪种情绪"。 | 矩阵让用户不再在海量评论中迷失，聚焦到最关键的内容单元。 |
| US-6.2 | 作为内容策略师，我想看到**卖点效果排名**（哪个卖点正面共鸣最强、哪个引起最多质疑），以便优先调整效果最差的卖点。 | 排名直接指导内容优化优先级，减少主观猜测。 |
| US-6.3 | 作为品牌方负责人，我想看到**内容缺口报告**（用户想知道但内容没说到的话题），以便规划下一期内容的选题方向。 | 缺口报告将"评论区呼声"转化为内容选题，建立数据驱动的选题机制。 |
| US-6.4 | 作为策略师，我想在归因矩阵中**点击任一内容要点，查看它的代表性评论原文和证据链**，以便验证AI判断是否可信。 | 可追溯性是AI产品建立用户信任的底线要求。 |
| US-6.5 | 作为代运营公司负责人，我想看到每个要点的**影响度评分（1-10）和评论数量分布**，以便向客户汇报时用数据说话。 | 量化数据使报告更有说服力，支撑客户续约决策。 |

### 2.2 模块9：内容生产卡（核心新增）

| # | 用户故事 | 价值说明 |
|---|---------|---------|
| US-9.1 | 作为内容创作者，我想拿到一份**包含脚本结构、文案全文、素材规格的生产卡**，以便直接进入拍摄环节，不需要二次解读。 | 将AI分析直接转化为可执行方案，减少"分析到执行"的转化损耗。 |
| US-9.2 | 作为策略师，我查看生产卡时**必须看到 card_type（抖音/小红书标识）、title、hook_strategy、script_structure、copywriting、selling_points 和 supporting_evidence**（7个核心字段），以便3秒内判断这份卡是否"可用"。 | 21个字段不能全部平铺展示——7个核心字段应作为首屏信息，其余折叠展现。 |
| US-9.3 | 作为面向抖音的用户，我希望生产卡**侧重钩子策略、前3秒爆发文案和视觉冲击素材规格**，以便匹配抖音的算法分发逻辑。 | 平台差异化是核心竞争力——同一份洞察生成不同平台的生产卡。 |

| US-9.5 | 作为创作者，我想看到每一条卖点**对应的评论区证据**（支持性证据链），以便在创作时心里有底、敢于强化这个卖点。 | 证据链减少"AI写的瞎话我不敢用"的心理障碍。 |

### 2.3 模块12：发布前质检（核心新增）

## 4. 关键验收标准（P0需求）

### BL-001 品类知识库后端

- [ ] `category_knowledge` 表创建成功，支持 CRUD API
- [ ] 美妆品类种子数据至少包含：8条典型需求（如"补水保湿""淡化细纹""不粘腻"）、6条典型购买障碍（如"怕过敏""觉得太贵""效果不明显"）、4个人群画像

- [ ] 障碍标签结构包含：code、label、description、frequency（出现频率 HIGH/MEDIUM/LOW）

## 5. 待确认问题

### Q1. 品类知识库先从美妆切入，还是多品类同时铺开？

**背景**: 蓝图建议初期手工构建美妆+食品两个品类。美妆品类数据相对容易获取（当前系统已有美妆demo数据），但用户可能是做食品或日化。

**待确认**: 是先把美妆做深做透（15条需求+10条障碍+精标竞品），验证体系后再扩展？还是一开始就铺食品/健康/日化至少3个品类（但每个品类数据较浅）？

**影响决策**: 归因Agent的Prompt设计和品类知识库的表结构是否需要多品类联合推理能力。

---

### Q2. 质检结果：全自动放行还是人工最终复核？

**背景**: 蓝图将质检设计为Agent驱动的9项检查（合规/一致性/卖点/受众/平台/竞品/敏感词/可执行/完整性）。Agent质检的一致性不如人工确定性高。

**待确认**: 
- 方案A：质检全自动，pass的直接放行，warning/fail的推送到人工审核队列
- 方案B：质检全自动+全部需要人工确认（增加了操作步骤但确保安全）
- 场景考虑：内部品牌方用户（犯错了内部扣钱）vs 代运营公司用户（犯错了丢客户）

**影响决策**: `quality_checks` 表的 reviewer 字段处理逻辑 + 前端质检流程的交互设计。

---

### Q3. 内容生产卡：仅查看还是支持在线编辑？

**背景**: 21字段生产卡，蓝图定义的状态流转为 draft→reviewed→approved→published。用户拿到卡后是否需要在系统内修改？

**待确认**:
- 方案A：生产卡仅查看+导出（用户导出后在外部编辑器修改和拍摄）
- 方案B：生产卡支持在线编辑（用户可在系统内修改文案、调整脚本结构、保存版本）
- 考虑点：B方案需要版本管理和协作功能，工作量增加约30%

**影响决策**: 前端 ProductionCardsPage 是否需要 CardEditor 编辑器组件 + 后端 PUT /api/production-cards/:id 是否只更新元数据还是全量内容字段。

---

### Q4. 归因可信度如何向用户展示？

**背景**: 蓝图提到归因Agent幻觉风险是"高严重度"。用户看到"卖点1引发了正面共鸣，影响度8.5分"时，会问"你凭什么这么说？"

**待确认**:
- 方案A：仅展示代表性评论原文（让用户自己判断）——纯信息展示
- 方案B：展示证据数量（该要点关联了N条评论）+ 置信度分值（0-100%）——半量化
- 方案C：展示证据链 + 置信度 + 可下钻到逐条评论的审查面板（用户可标记"认同/不认同"来训练模型）——全透明+反馈闭环

**影响决策**: 归因工作台前端的证据展示层级和交互深度 + 是否需要用户反馈收集机制。

---

### Q5. 报告导出：自选模块导出还是全量固定模板导出？

**背景**: PDF/Excel导出是面对客户的关键功能，但不同用户场景需要的内容模块不同。

**待确认**:
- 方案A：固定模板（所有报告包含归因矩阵+生产卡+质检结果+原始数据附件打包，用户选择平台/时间范围）
- 方案B：模块化自选（勾选需要的模块：归因分析/卖点排名/生产卡/质检报告/原始评论数据，按勾选拼装报告）
- 考虑点：方案B更灵活但前端交互更复杂（模块多选→预览面积→确认导出）

**影响决策**: 报告导出API的模板引擎设计 + 前端导出设置页面的复杂度。

---

### Q6. 链接输入功能：系统自己抓评论，还是用户仍需手动导入？

**背景**: US-2.2 提出可直接粘贴视频/笔记链接，自动抓取评论启动分析。但这涉及到对外部平台的爬取和合规性。

**待确认**:
- 方案A：仅做链接保存（记录Original URL，用户仍需手动导入评论文件）
- 方案B：后端通过平台接口/爬虫自动抓取评论（需要解决反爬、Cookie、合规等问题）
- 考虑点：方案B是"一键体验"的核心但技术风险高（可能被平台封IP），方案A是安全的降级方案

**影响决策**: 模块2任务创建表单的交互设计 + 是否需要外部抓取技术服务。
