## 1. 产品目标

VOS 2.0 的核心商业目标是将系统从「个人分析玩具」升级为「可交付客户的专业工作站」：

| # | 目标 | 衡量标准 |
|---|------|---------|
| G1 | **多品牌并行运营** | 支持 10+ 品牌独立工作区，品牌切换 ≤2 秒，品牌间数据完全隔离 |
| G2 | **持续数据积累** | 支持每周 Excel 增量导入，自动去重（基于评论ID），增量 AI 分析 |
| G3 | **人机协同审核** | AI 产出 100% 经人工确认/编辑/驳回，审核日志可追溯 |
| G4 | **端到端可执行** | 策略卡可一键导出为投放 Brief（Excel），投放团队可直接执行 |
| G5 | **数据可视化** | 核心指标具备趋势图/对比图，支持按周/月查看变化 |

### 非目标（V2 不做）
- ❌ SaaS 化部署（仍为本地单机工作站）
- ❌ 实时数据接入（维持手动导入模式）
- ❌ 多人协作/权限管理（单用户场景）
- ❌ 飞书文档 API 集成导出（先做 Excel，飞书留 V2.1）

## 2. 用户画像

### 主要用户：老薛（代运营公司负责人）

| 维度 | 描述 |
|------|------|
| **角色** | 代运营公司老板/策略总监 |
| **日常工作** | 每周查看各客户品牌的评论数据 → 分析用户声音 → 制定内容投放策略 → 产出投放 Brief 交付给内容团队 |
| **痛点** | ① 每次切换品牌要重新导入数据、重新分析，无法并行管理多个客户；② AI 分析结果不可控，没法审核就直接用了，不敢给客户看；③ 策略停留在 PPT 级别，投放团队拿到后还得重新翻译成执行方案 |
| **使用频率** | 每周 2-3 次深度使用（导入数据 + 审核 AI 结果 + 导出 Brief） |
| **技术水平** | 无编程背景，熟悉 Excel，理解基本的数据分析概念（CTR、CVR、ROI） |

### 次要用户：内容/投放执行团队

| 维度 | 描述 |
|------|------|
| **角色** | 编导、文案、投手 |
| **日常工作** | 接收 Brief → 根据 Brief 制作内容 → 投放 → 回收数据分析效果 |
| **痛点** | Brief 不够结构化，缺乏评论证据支撑，测试变量不清晰 |
| **使用频率** | 按需查看（只读 Brief 输出） |

## 3. 核心用户故事

### Epic 1：多品牌管理

**US-1.1**  
As a 代运营公司负责人，  
I want 创建和管理多个品牌工作区，每个品牌有独立的评论数据、分析结果和策略卡，  
So that 我可以同时服务多个客户而不互相干扰。

**验收标准**：
- 可创建/编辑/删除品牌（品牌名、行业、Logo、基本配置）
- 品牌切换后，所有页面（评论池、需求地图、策略卡等）数据完全切换
- 支持至少 10 个品牌同时存储

**US-1.2**  
As a 代运营公司负责人，  
I want 品类级标签体系（人群标签、购买障碍、场景标签等）可以在品牌间共享，  
So that 服务同品类客户越多，系统越懂这个品类。

**验收标准**：
- 标签体系在"品类知识库"中统一定义
- 品牌可选择关联某个品类，自动继承品类标签
- 品牌也可添加自有标签（不污染品类级标签库）

---

### Epic 2：持续导入与增量分析

**US-2.1**  
As a 代运营公司负责人，  
I want 每周导入 Excel 评论数据时系统自动去重（同评论ID不重复计入），  
So that 不会因重复导入而污染分析结果。

**验收标准**：
- 导入时基于 `评论ID`（优先）或 `内容哈希`（备选）去重
- 重复评论显示"已跳过 X 条重复"提示
- 保留导入历史：什么时间导入了多少条、来源平台

**US-2.2**  
As a 代运营公司负责人，  
I want 新评论导入后 AI 分析结果在历史基础上增量更新（而非全量重跑），  
So that 我能看到本周新增了什么洞察，以及和历史对比的趋势变化。

**验收标准**：
- 导入新评论后，AI 只分析新增评论
- Dashboard 显示「本周新增洞察 vs 累计洞察」
- 策略卡显示「基于 N 条新评论更新」的标记
- 数据按周归档，可查看历史每周快照

---

### Epic 3：人机协同审核

**US-3.1**  
As a 代运营公司负责人，  
I want AI 生成的每条洞察/策略都带置信度标记并进入审核队列，  
So that 我可以确认、编辑或驳回 AI 的结果，确保交付给客户的内容质量。

**验收标准**：
- AI 产出默认状态为「待审核」，显示置信度（高/中/低）
- 审核操作：✅ 确认（状态变为「已确认」）、✏️ 编辑（覆盖 AI 内容后确认）、❌ 驳回（状态变为「已驳回」，附驳回理由）
- 审核工作台有筛选器：全部/待审核/已确认/已驳回

**US-3.2**  
As a 代运营公司负责人，  
I want 查看审核日志——谁在什么时间确认/编辑/驳回了什么内容，  
So that 我可以追溯决策过程，向客户解释策略依据。

**验收标准**：
- 每条审核记录包含：操作人、时间戳、操作类型、变更前后对比
- 审核日志可按品牌、时间范围筛选
- 支持导出审核日志（CSV）

---

### Epic 4：端到端可执行

**US-4.1**  
As a 代运营公司负责人，  
I want 将已确认的策略卡一键导出为投放 Brief（Excel 格式），  
So that 投放团队拿到 Brief 就能直接执行，无需二次翻译。

**验收标准**：
- Brief 包含：策略标题、评论证据摘要（3-5 条原文引用）、内容方向建议、A/B 测试变量、预期 KPI、预算建议
- 导出格式：Excel（.xlsx），每个策略一个 Sheet
- 导出文件名：`{品牌名}_投放Brief_{日期}.xlsx`

**US-4.2**  
As a 代运营公司负责人，  
I want 查看策略卡的数据可视化（趋势图、对比图），  
So that 我可以直观地向客户展示数据支撑的策略逻辑。

**验收标准**：
- Dashboard 包含：评论量趋势（按周）、需求/障碍分布饼图、竞品声量对比柱状图
- 图表可交互（悬停显示具体数值）
- 图表数据随品牌切换而更新

---

### Epic 5：系统修复

**US-5.1**  
As a 代运营公司负责人，  
I want 报告中心能真正生成可下载的报告（非空壳），  
So that 我可以直接交付给客户或内部使用。

**US-5.2**  
As a 代运营公司负责人，  
I want 品牌知识库的数据能被 AI 分析引用（竞品信息、产品卖点、内容指南），  
So that AI 产出的策略更贴合品牌实际情况。

**US-5.3**  
As a 代运营公司负责人，  
I want 全局搜索能跨模块搜索（评论、策略卡、品牌信息），  
So that 我可以快速找到相关信息。

## 4. 功能需求池

### P0 — 必须实现（阻断性功能，无此功能 V2 无法交付）

| ID | 功能 | 描述 | 验收标准 |
|----|------|------|---------|
| **F-001** | 多品牌数据模型 | 底层数据结构从单品牌改为多品牌，所有数据挂载 brand_id | 每个 brand_id 隔离评论、策略卡、分析结果；品牌切换时 UI 数据完全刷新 |
| **F-002** | 品牌管理页 | 品牌列表（卡片视图）+ 新建/编辑/删除品牌 | 支持品牌名、行业、Logo URL、竞品列表配置；删除品牌需二次确认 |
| **F-003** | 品牌切换器 | 顶部导航栏增加品牌下拉切换 | 切换后所有页面数据更新；记录上次选择的品牌（localStorage） |
| **F-004** | 评论去重导入 | 导入时基于评论ID去重，显示导入摘要 | 去重逻辑：① `videoId + userUid + content哈希` 组合键；② 显示"成功 X 条，跳过 Y 条重复" |
| **F-005** | 增量 AI 分析 | 只分析新增评论，结果追加而非覆盖 | AI 分析范围仅限 `isAnalyzed === false` 的评论；Dashboard 指标仅基于当前品牌数据计算 |
| **F-006** | 审核工作台 | 独立页面，AI 产出物列表 + 三态审核 | 筛选器（全部/待审核/已确认/已驳回）；批量确认/驳回；审核日志记录 |
| **F-007** | Brief 导出 | 策略卡→Excel 导出 | 至少包含：策略标题、证据引用、内容方向、测试变量、预期KPI；导出一个 .xlsx 文件 |
| **F-008** | 清除 demo 数据 | 移除硬编码的 28 条示例评论和品牌数据 | 首次启动显示引导页（创建第一个品牌 + 导入第一批数据） |

### P1 — 应该实现（核心体验，提升专业度）

| ID | 功能 | 描述 | 验收标准 |
|----|------|------|---------|
| **F-009** | 数据可视化 Dashboard | 评论量趋势折线图、需求/障碍分布饼图、竞品声量柱状图 | 使用 Chart.js 或 ECharts（轻量）；至少 3 种图表类型 |
| **F-010** | 品牌知识库参与 AI 推理 | AI 分析 prompt 中注入当前品牌的 product info、competitor data、content guidelines | 策略卡产出明显体现品牌个性；审核时可对比有无品牌知识库的差异 |
| **F-011** | 报告中心实现 | 至少实现「老板汇报版」和「客户汇报版」两类报告 | 报告基于已确认的分析结果生成；支持导出 PDF（浏览器打印）或 Markdown |
| **F-012** | 全局搜索 | 顶部搜索栏，跨模块搜索评论、策略卡、品牌信息 | 300ms debounce；搜索结果按模块分组；支持中文分词 |
| **F-013** | 周/月数据归档 | 每周自动快照关键指标，支持历史对比 | Dashboard 可切换查看历史周；对比视图（当前周 vs 上周） |
| **F-014** | 导入历史 | 记录每次导入的时间、数量、来源平台 | 列表视图；可查看每次导入的评论明细 |
| **F-015** | 内容池与评论池交叉引用 | 策略卡中关联相关内容和相关评论 | 策略卡详情页同时展示：评论证据 + 参考内容案例 |

### P2 — 可以后续迭代（增强体验）

| ID | 功能 | 描述 |
|----|------|------|
| **F-016** | 飞书文档导出 | Brief 直接导出为飞书文档格式 |
| **F-017** | 策略效果追踪 | 投放后回填实际 KPI，对比预期 vs 实际 |
| **F-018** | 竞品监控 Dashboard | 竞品评论量变化、竞品策略卡自动生成 |
| **F-019** | 邮件/飞书定时推送 | 每周自动推送报告摘要 |
| **F-020** | 数据备份/恢复 | 一键导出全量数据（JSON），支持跨设备迁移 |

### 6.3 localStorage 存储策略变更

| V1 Key | V2 替代方案 |
|--------|-----------|
| `voc-comments` | `vos2_comments_{brandId}` 或 IndexedDB 统一存储 |
| `voc-brand-data` | `vos2_brands`（所有品牌配置） |
| `voc-benchmark-data` | 合并到 `vos2_brands.{brandId}.competitors` |
| `voc-api-settings` | `vos2_settings`（保持） |
| `voc-call-logs` | `vos2_call_logs`（保持） |
| — | `vos2_insights_{brandId}` |
| — | `vos2_cards_{brandId}` |
| — | `vos2_import_history_{brandId}` |
| — | `vos2_snapshots_{brandId}` |
| — | `vos2_categories`（品类共享数据） |

> **风险提示**：localStorage 5MB 上限。10 个品牌 × 每个品牌 2000 条评论 ≈ 可能接近上限。  
> **建议方案**：使用 IndexedDB 存储评论数据和审核日志，localStorage 仅存储品牌配置和设置。

## 7. 技术架构建议

### 7.1 推荐技术栈

| 层面 | 推荐 | 理由 |
|------|------|------|
| 框架 | Vite + React + TypeScript | 从单文件 HTML 升级到工程化项目；类型安全对多品牌数据结构很重要 |
| UI 库 | MUI (Material UI) + Tailwind CSS | MUI 提供成熟的数据表格、对话框、表单组件；Tailwind 保留现有设计风格 |
| 状态管理 | Zustand | 轻量、适合中等复杂度应用；支持 persist 中间件同步 localStorage |
| 存储 | IndexedDB (Dexie.js) | 突破 5MB 限制；支持复杂查询（按 brand_id、时间、审核状态过滤） |
| 图表 | Recharts 或 ECharts | 数据可视化核心需求 |
| Excel 导出 | SheetJS (xlsx) | V1 已在用，延续 |
| 构建 | Vite | 快速 HMR，适合 2-3 人团队 |

### 7.2 迁移策略

V1（纯 HTML 单文件）→ V2（React SPA）建议采用**重写**而非渐进式迁移：

1. 保留 V1 的：评论导入逻辑（normalizeComments）、AI 调用逻辑（callLLM）、API 配置加密逻辑
2. 重写的：数据模型、页面路由、状态管理、UI 组件
3. V1 数据兼容：首次启动 V2 时，读取 V1 的 `voc-comments` 数据，自动迁移到第一个品牌的 `brand_001` 下
